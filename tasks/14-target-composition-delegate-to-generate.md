## Problem

`target/setup-project.sh` installs the target's task system by **copying
create-ai-builder's own `project/tasks/scripts/`** into the target. After task 09
those scripts are themselves generated by create-project-system, so it's now a
**copy-of-a-copy** (two drift points), and the script hand-re-implements epic
scaffolding + CLAUDE.md init that `generate.sh` already does better.

## Goal

Refactor the target install into two explicit layers (see design doc):

1. **Layer 1 (task system) — delegate to `generate.sh`.** Call a **pinned**
   create-project-system `generate.sh` against the target with
   `--tasks-dir project/tasks --with-status --with-skill --inject-claude-md`
   (plus `--with-classes`/`--with-projects`/`--with-worktree-guard` as the target
   needs). This lands **all** of: the task machinery, `docs/USING.md`, the
   `task-system` **skill** (`.claude/skills/…`), and the `## Task tracking`
   **CLAUDE.md** block — all three insertions are required in the target.
2. **Layer 2 (pipeline overlay) — create-ai-builder's own.** Install the 7
   pipeline scripts + orchestrator/roles/machines **on top**. This layer does
   **NOT** come from `generate.sh` — it is create-ai-builder's hand-maintained code.

## Decisions

- **Pinned version (decided).** create-ai-builder pins a specific
  create-project-system version so target installs are reproducible.
  - [ ] Choose mechanism: git submodule at a pinned commit **vs** vendored
        snapshot at a tag. (Lean: submodule for explicit provenance.)
  - [ ] Record the pin + a documented "bump the pin" procedure.

## Done when

create-project-system** (skill + USING.md + CLAUDE.md block included) and whose
**pipeline layer is create-ai-builder's own overlay** — no copy-of-a-copy, and
the composition is documented in the design doc.
